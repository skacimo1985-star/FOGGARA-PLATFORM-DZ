## Implemented
- Arabic RTL, French and English agricultural workspace, responsive layouts and reduced-motion support.
- Organization-scoped parcels, sourced observations, independent evidence review, crop tasks, and immutable irrigation scenario snapshots with audit events.
- pH/N/P/K/SOC/EC/moisture/NDVI/LSWI record capture with units, timestamps and bounds. Chemistry is entered from a lab/field source, not inferred from satellites.
- Irrigation scenario: `ETc=ETo*Kc*days`, `net=max(0,ETc-effective_rain)`, `gross=net/efficiency`, `m3=gross*ha*10`.
- Revenue arithmetic using user-entered assumptions; no prices, market forecasts or guaranteed profit.
- Existing service catalog/request workflow remains the authenticated service entry point.
- Export of currently loaded records to JSON. List endpoints currently cap parcels/plans at 500 and observations/tasks at 1000; not a complete archival export for larger datasets.
- Optional read-only browser WebMCP tool, feature detected. Validation unavailable in a supported browser context here.
- JWT no longer saved on disk by the frontend; login is required after refresh. Unknown API paths return 404, and SPA file paths are confined to build output.
- New reversible Alembic migration, preserving earlier migrations.

## Exact status
This is an implemented agricultural extension and private interactive preview, NOT certification of a complete production platform. The preview stores synthetic edits only in memory and resets on reload. It does not connect to the FastAPI server. The operational application stores records in the configured database and requires authentication.

## Scientific references
- FAO 56, chapter 5: https://www.fao.org/4/X0490E/x0490e0a.htm — crop coefficient relation under standard conditions.
- USGS NDVI: https://www.usgs.gov/landsat-missions/landsat-normalized-difference-vegetation-index — normalized difference on scaled surface reflectance.
The irrigation model is a simplified scenario, not a full FAO56 soil-water balance or salinity/stress model. ETo and Kc are user supplied; source strings do not independently validate inputs. No actuator control, pesticide dosing, automated disease diagnosis or soil-chemistry prediction is enabled.

## Running the operational application
Use the existing deployment instructions in README. From `app/backend`, install `requirements.txt`, set the database/environment, run `alembic upgrade head`, then `uvicorn app.main:app`. Build the frontend from `app` with `npm ci` and `npm run build`; the backend serves `dist` on the same origin. Production requires `ENV=prod`, a PostgreSQL URL and a strong unique JWT secret. Do not use the demo seed in production.

## Business starting point
The present code supports a path from registered plots and sourced measurements to reviewable reports and service requests. Subscription and per-study pricing must be validated with actual customers and delivery costs. The calculator is a worksheet for those assumptions, not a revenue promise.
